# Translations (i18n)

The web UI ships in English (the default, always), Spanish, French, Russian and German. The runtime is [lib/i18n.js](../src/web/public/lib/i18n.js); the dictionaries are [lib/i18n/{es,fr,ru,de}.js](../src/web/public/lib/i18n/).

## How a string is translated

- **The English text is the key.** `t('Leaderboard')` returns the dictionary entry for `'Leaderboard'`, or the English when there is none. Interpolate with `{name}` placeholders: `t('Deleted {name}', { name: esc(name) })` — t() never escapes, so escape the values exactly as the English template did.
- **Plurals go through `tn()`**: `tn(count, '{n} chest', '{n} chests')`. The dictionary entry is keyed by the plural and holds the language's forms — Russian needs `one`/`few`/`many`, the others `one`/`other`. Never hand-roll `count === 1 ? … : …` in UI text.
- **Only string literals** go into t()/tn() — no variables, no `${}` templates. The build parses them; anything else fails the guard.
- **Whole sentences**, never concatenated fragments: word order differs between languages. Markup with attributes goes in a placeholder, not in the key.
- **Static markup in the HTML shells** uses `data-i18n` (the element's text) and `data-i18n-attr="title aria-label"` (those attributes). i18n.js translates them on load.

## Game names: `tGame()`, official only

Chest names, chest sources, events and resources are the game's words, and a player matches them against their own game client. `tGame(name)` returns the **official** in-game name from the dictionary's `game` block, and the English otherwise. A plausible translation that isn't the game's own is worse than English — it sends someone looking for a name that doesn't exist — so the `game` block only takes names with a source (game locale data, totalbattle.com in that language, official help pages). Names with numbers match patterns: `'Level {n} epic Crypt'`.

Use tGame() only where a name is displayed — never in data-* attributes, URLs, select values, sort keys or anything sent back to the server. The data itself stays English: the scanner reads an English client.

## The choice, and where it lives

- Like the theme: localStorage (`lang`) for this browser, plus `users.language` (v89) for a signed-in account so it follows the person. `''`/null on the account = never chosen; the browser's choice is then adopted on sign-in (`adoptAccountLanguage`). The server's value wins when set.
- English is the default whatever the browser says — no `Accept-Language`, no `navigator.language`.
- **A change reloads the page.** Strings are baked into rendered HTML and module-level constants; a reload is the only way to re-render all of them.
- Pickers: the user menu and the phone drawer (signed in), next to the theme select on the public share page, and under the login form.
- **No English flash**: an inline bootstrap in `index.html`, `login.html` and `public-share.html` hides the page for a saved non-English language until i18n.js has translated the shell, with a 2.5 s CSS reveal as the safety net. The three copies are kept identical by `tests/config/i18n-bootstrap.test.ts`.
- i18n.js loads the dictionary with a top-level `await import()`, so every importer can call t() at module level. A dictionary that fails to load falls back to English; it can never take the module graph down.

## Adding or changing a string

1. Wrap it in t()/tn() (or `data-i18n` in a shell).
2. Run `npx tsx scripts/i18n-sync.ts missing out.json` for the work list, translate, and merge with `npx tsx scripts/i18n-sync.ts merge <lang> <file.json>` (it also drops entries the source no longer uses and keeps the files grouped by source file).
3. `npm run build` — `tests/config/i18n-dictionaries.test.ts` fails on any untranslated or stale entry, a placeholder or HTML tag that differs from the English, a bare `"` (it would end the attribute the string sits in), or a missing plural form.

Changing English text changes its key: every language needs the new entry, and the old one is reported stale.

German and Russian run 30–60% longer than English, and several tables lock their column widths. For anything layout-sensitive, the `local-ui-check` skill ([.claude/skills/local-ui-check/SKILL.md](../.claude/skills/local-ui-check/SKILL.md)) runs the dashboard locally on a sanitized copy of the newest backup and screenshots every page in all five languages at desktop and phone widths, flagging overflow and clipped text relative to English.

## Not translated

- Server messages (API errors, System-page log entries, Discord posts) are English. The login page maps its few known server errors.
- The setup wizard (a one-time operator flow) is English.
- Numbers keep the browser's formatting (`toLocaleString()`), dates stay ISO, year first. Month and weekday names follow the chosen language.
